# Typizer SDK для 1С:Предприятия 8.3

Два общих модуля, которые подключают API Typizer к **любой** конфигурации: УТ, КА, ERP, доработанная
«Бухгалтерия», самописная. Отправили скан или PDF со своей схемой — получили данные документа
структурами 1С (`Соответствие`, `Массив`), проверки полей и понятные ошибки.

- Платформа **8.3.17 и новее**, управляемое и обычное приложение, файловый и клиент-серверный вариант.
- **Без БСП** и без объектов конфигурации: ни `ОбщегоНазначения`, ни `ДлительныеОперации`, ни справочников.
- Ошибки — структурой (`Код`, `Текст`, `КодСостояния`), а не исключениями. Ключ API передаёте вы: SDK его не
  хранит и не пишет в журнал регистрации.
- `Retry-After` на 429/503, ключ идемпотентности на каждый файл, ожидание результата с таймаутом.

Полная инструкция — [docs.typizer.ru/how-to/1c-sdk](https://docs.typizer.ru/how-to/1c-sdk).

## Установка

**Вариант 1 — расширение.** `typizer-1c-sdk.cfe` подключается в «Конфигурация → Расширения конфигурации»
(или «Администрирование → Расширения»). У расширения **снимите флажок «Безопасный режим»** — иначе 1С
запрещает HTTP-запросы. Обновлять SDK — заменить файл расширения, конфигурацию снимать с поддержки не нужно.

**Вариант 2 — модули в конфигурацию.** Создайте два общих модуля с этими именами и флажками и вставьте в них текст
файлов `ТипизаторAPI.bsl` и `ТипизаторAPIКлиентСервер.bsl` (в репозитории —
`src/CommonModules/<Модуль>/Ext/Module.bsl`):

| Модуль | Сервер | Внешнее соединение | Клиент (управляемое приложение) | Клиент (обычное приложение) | Вызов сервера |
|---|---|---|---|---|---|
| `ТипизаторAPI` | ✓ | ✓ | — | — | — |
| `ТипизаторAPIКлиентСервер` | ✓ | ✓ | ✓ | ✓ | — |

Имена модулей менять нельзя: модули вызывают друг друга по имени.

Модули SDK подключаются в базу один раз: если они уже пришли с другим расширением (например, с примером для
«Бухгалтерии» из `../examples/bp`), второе расширение SDK не нужно — две копии конфликтуют по именам.

## Быстрый старт

```bsl
// Серверный код. КлючAPI — из вашего хранилища (см. «Где хранить ключ»).
Подключение = ТипизаторAPI.НовоеПодключение(КлючAPI);
Параметры = ТипизаторAPI.ПараметрыПрогона();
Параметры.Схема = "{""type"":""object"",""properties"":{""seller_inn"":{""type"":""string""},""total"":{""type"":""number""}}}";

Результат = ТипизаторAPI.РаспознатьФайл(Подключение, ДвоичныеДанные, "Счёт №15.pdf", Параметры);
Если Не Результат.Успех Тогда
	ВызватьИсключение Результат.Ошибка.Текст;
КонецЕсли;
ИННПродавца = ТипизаторAPIКлиентСервер.ЗначениеПоля(Результат.Данные, "seller_inn");
Сумма = ТипизаторAPIКлиентСервер.ЗначениеПоля(Результат.Данные, "total");
```

Вместо схемы можно указать сохранённый в кабинете типизатор: `Параметры.ИдентификаторТипизатора = "tz_…"`.
Схему можно собрать и структурами 1С: `Структура` сохраняет порядок свойств (он задаёт порядок полей результата),
`Соответствие` — нет; его оставьте для ключей вроде `$defs`. По той же причине `Результат.Данные` и `Результат.Поля`
(`Соответствие` из `ЧтениеJSON`) читайте по именам и путям, а не по порядку.

Штрихкоды и QR-коды на документе (платёжный QR квитанции, QR чека, «Честный знак») сервис читает сам и берёт
из них данные для полей вашей схемы: ИНН, сумма или GTIN из кода попадают в `Результат.Данные`, если такие поля
есть в схеме. Отдельного списка кодов в результате нет. Поле, которое расходится с кодом, получает в
`Результат.Поля` статус `warn` с причиной `code_mismatch`.

## Программный интерфейс

### `ТипизаторAPI` (сервер, внешнее соединение)

| Функция | Что делает |
|---|---|
| `НовоеПодключение(КлючAPI, АдресСервиса = "", ДополнительныеПараметры = Неопределено)` | Подключение; сетевых запросов нет. Параметры — `ПараметрыПодключения()`: `ТаймаутСекунд` (150), `Прокси` (`ИнтернетПрокси`), `МаксимумПовторов` (5), `Приложение` (`"MyERP/2.4"` в User-Agent). |
| `ПараметрыПрогона()` | `Схема` (строка JSON, `Соответствие` или `Структура`) **или** `ИдентификаторТипизатора`; `Указания`, `Режим` (`"standard"`/`"precise"`), `Метаданные`, `КлючИдемпотентности`, `ОжиданиеСекунд` (0–60), `АдресВебхука`. |
| `РаспознатьФайл(Подключение, ДвоичныеДанные, ИмяФайла, ПараметрыПрогона, ТаймаутСекунд = 900)` | Отправить и дождаться результата. |
| `СоздатьПрогон(Подключение, ДвоичныеДанные, ИмяФайла, ПараметрыПрогона)` | Только отправить (`POST /v1/extract` или `/v1/typizers/{id}/runs`). |
| `ПолучитьПрогон(Подключение, ИдентификаторПрогона)` | Текущее состояние (`GET /v1/runs/{id}`). |
| `ОжидатьПрогон(Подключение, ИдентификаторПрогона, ТаймаутСекунд = 900, ИнтервалОпросаСекунд = 2)` | Опрос до завершения; временные сбои (нет связи, 429, 5xx) не прерывают ожидание. |
| `ПолучитьПрофиль(Подключение)` / `ПолучитьБаланс(Подключение)` | `GET /v1/me` — организация и права ключа; `GET /v1/balance` — `pages_available`. |
| `ВыполнитьЗапрос(Подключение, Метод, Путь, Тело, ДополнительныеЗаголовки)` | Любая другая операция API; тело-строка уходит как JSON. |
| `JSONВЗначение(Текст)` / `ЗначениеВJSON(Значение)` / `Пауза(Секунд)` / `ТелоMultipart(Части, Граница)` | Вспомогательные. |

Результат любой функции — `Структура`:

| Поле | Тип | |
|---|---|---|
| `Успех` | Булево | Для `РаспознатьФайл`/`ОжидатьПрогон` — прогон успешно завершён. Для `СоздатьПрогон`/`ПолучитьПрогон` — запрос выполнен, прогон мог ещё не завершиться. |
| `Ошибка` | Неопределено, Структура | `Код`, `Текст` (по-русски, можно показать пользователю), `КодСостояния`, `Подробности`, `ИдентификаторЗапроса`. |
| `КодСостояния` | Число | Код ответа; 0 — ответа не было. |
| `Данные` | Соответствие, Массив | Результат распознавания (`output`) или тело ответа `ПолучитьПрофиль`/`ПолучитьБаланс`. |
| `ИдентификаторПрогона`, `Статус`, `Завершен` | Строка, Строка, Булево | Только у прогонов: `run_…`; `queued`/`processing`/`succeeded`/`failed`. |
| `Поля` | Соответствие | Проверки полей (`fields`): путь → `status`, `reason`. |
| `Прогон` | Соответствие | Весь объект прогона. |
| `КлючИдемпотентности` | Строка | С ним можно безопасно повторить отправку. |

Коды ошибок SDK (кроме кодов API): `api_key_missing`, `invalid_argument`, `connection_failed`, `timeout`,
`output_expired`, `invalid_response`, `client_error`.

Соответствие REST API и SDK для TypeScript/Python (для общей спецификации SDK Typizer):

| 1С | REST | TypeScript (`typizer`) |
|---|---|---|
| `НовоеПодключение` | — | `createTypizerClient` |
| `СоздатьПрогон` со `Схема` | `POST /v1/extract` | `extract` |
| `СоздатьПрогон` с `ИдентификаторТипизатора` | `POST /v1/typizers/{id}/runs` | `createRun` |
| `ПолучитьПрогон` | `GET /v1/runs/{id}` | `getRun` |
| `ОжидатьПрогон` | опрос `GET /v1/runs/{id}` | — (ожидание прогона в общей спецификации) |
| `РаспознатьФайл` | `POST /v1/extract?wait=60` + опрос | — |
| `ПолучитьПрофиль` | `GET /v1/me` | `getMe` |
| `ПолучитьБаланс` | `GET /v1/balance` | `getBalance` |
| `Результат.Ошибка.Код` | `code` из Problem | `error.code` |

### `ТипизаторAPIКлиентСервер` (клиент и сервер)

`ЗначениеПоля(Данные, "items[0].amount")`, `ПоляНаПроверку(Поля)` (массив `Путь`, `Статус`, `Причина`),
`ЧислоИзЗначения`, `ДатаИзСтроки`, `СтрокаИзЗначения`, `ТолькоЦифрыИзСтроки`, `ТекстОшибки(КодСостояния, КодОшибки, Подробности)`,
`ЭтоВременнаяОшибка(Ошибка)`, `НормализованныйАдресСервиса`, `ВерсияSDK()`.

## Где хранить ключ

SDK принимает ключ параметром — где его хранить, решает конфигурация:

- **Есть БСП** — `ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище(Владелец, Ключ, "КлючAPI")` и чтение в
  привилегированном режиме только на сервере.
- **Нет БСП** — константа или регистр сведений, доступные только роли администратора; читайте ключ в
  привилегированном режиме и не передавайте на клиент.

## Распознавание в фоне

`РаспознатьФайл` ждёт результат (обычно секунды, у многостраничных сканов — дольше) и держит сеанс. Запускайте его
в фоновом задании: `ФоновыеЗадания.Выполнить(...)` или, с БСП, `ДлительныеОперации.ВыполнитьВФоне(...)`. Много
файлов — сначала `СоздатьПрогон` для каждого, затем `ОжидатьПрогон`: сервис распознаёт их параллельно.


## Исходники

`src/` — выгрузка Конфигуратора (формат 2.20) расширения `ТипизаторSDK`; загружается через
`/LoadConfigFromFiles <путь> -Extension ТипизаторSDK`. Готовые `.cfe` и `.zip` — в релизах репозитория.
